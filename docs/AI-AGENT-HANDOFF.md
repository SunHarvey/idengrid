## 对话中已确认的产品边界

- 品牌为 **IdenGrid／澜序**，标语为“环境独立，协作从容”。Linux Edge、控制端和客户端是同一产品的不同交付层；视觉调整不得悄悄改变浏览器签名身份、Profile/钥匙串兼容性或网络链路。
- 已决定停止云端 Chromium/Selkies 视频浏览器路线。目标是**本机清晰渲染**：本地浏览器和独立持久 Profile，经每店铺 Rust Agent、本机回环 SOCKS、认证 WSS 到获授权 Edge，再使用固定公网出口。不要把 SSH 隧道设计成用户侧产品流程，也不要让断线退化为本机直连。
- 管理员按用户授权可用的固定 Edge；普通用户只能看到并连接获授权节点。不同用户可以同时使用**同一 Edge/固定出口 IP**，但用户/设备/店铺的 Profile、Cookie、Agent、会话和租约必须隔离；租约不应把整台 Edge 全局锁给一个用户。新旧机器不可同时使用同一份活动 Profile。历史/标签快照跨设备同步是产品目标，不能据此声称已验收交付。
- 首版客户端范围：Apple Silicon macOS（SwiftUI 管理端＋内置标准 Chromium＋Rust Agent，不维护 Chromium fork）以及 Windows 11 x86-64（.NET 10/WPF 管理端＋浏览器运行时＋Rust Agent）。Windows Server 2025 是 Edge 服务目标，不是 Windows 桌面客户端的公开支持范围。macOS 开发包可用 CLT 和 ad-hoc 签名；正式发布仍需 Developer ID、公证和目标设备验收。
- 当前要求每个 macOS 店铺在 Dock 显示自己的店铺名；早期“统一 `IdenGrid Browser` Dock 身份”是旧首版方案，不应覆盖后来的要求。实现时仍不得擅自改变内置 Chromium 的签名身份或破坏旧 Profile/Cookie；此项是否已在最终包中达标须重新实测。延迟展示应区分中央节点参考值和本机至实际 Edge 的动态实测值。
- Windows 店铺须在任务栏有独立名称/身份；中文图标文字严格取店铺名第一个汉字，英文/数字最多取前两位并大写，不做语义别名。界面中文文案、Logo、状态与信息层级应参照已验收的 macOS 版本，不以占位 UI 代替。

## 沟通中反复确认的工程约束

- 先确认功能范围，再讨论重大架构，确认后编码；只处理本次明确范围，必要修复与架构增强分开。不要为了文档或测试自行部署生产、增加 GitHub Actions/Workflow、扩大线上验收路径，或在生产 Edge 编译完整 Chromium。
- 域名、数据库连接、节点 Endpoint/IP 与其他环境值只由受保护配置或构建输入注入；公开仓库只留示例和保留测试地址。不将固定长期密码注入浏览器；Token 不放进命令行、环境变量或日志；密码等凭据只能按既有受保护配置渠道传递，不暴露于普通命令、Issue、提交或审计。Cookie、私钥、Profile 内容与能力型 URL 同样不得外泄。正常 Refresh Token 轮换不写审计；重放/重复使用要保留安全事件。
- 保持原有 `SECRET_KEY`，除非单独设计并批准完整轮换。数据库现以 MySQL 为准，旧 SQLite 是历史回滚备份；不可把它当当前数据源。种子拓扑和管理员建号并非通过重启持续同步，详见 [运维说明](OPERATIONS.md#配置与服务映射)。
- 代码、本机运行、签名交付、真实用户链路和生产发布是不同验收等级。检查旧进程退出后再从**确切的最终包**启动新版；单独跑 Brave、做 SOCKS `curl`、检查 ZIP 哈希或源树单测，都不能证明完整客户端、DNS/WebRTC/QUIC 防泄漏或 Fail Closed。
- 不推断历史主机状态：远程主机角色、访问权限、当前配置、备份、包保管位置和回滚负责人必须由授权人通过受保护资产记录提供。对公网仓库仅留下匿名化证据；商业使用依 [许可](../LICENSE)，品牌依 [商标边界](../TRADEMARKS.md)，浏览器运行时再分发权另依第三方条款审查。
